PHASE 1: RESUME INGESTION & 5-PILLAR ATS BENCHMARK SCORING ENGINE
--------------------------------------------------------------------------------
Status: [COMPLETED]
Primary Objectives:
  - Provide multi-format candidate resume ingestion (.PDF and .DOCX).
  - Extract candidate contact details, skills, experience, education, projects, 
    and summaries with high accuracy.
  - Implement an industry-standard 5-Pillar ATS scoring benchmark to evaluate 
    resume parsing efficacy before applying.
  - Support an interactive drag-and-drop resume editor allowing section reordering 
    and live content editing.

Files & Components Involved:
  - Backend: `backend/app/agents/agent1_parser.py`, `backend/app/db/models.py` (`ProfileModel`), 
    `backend/app/schemas/schemas.py` (`ProfileSchema`, `ReorderRequest`), `backend/app/main.py`
  - Frontend: `frontend/src/components/ResumeUploader.jsx`, `frontend/src/components/ResumeAnalyzer.jsx`, 
    `frontend/src/components/DragDropResumeEditor.jsx`
  - Test Suite: `backend/test_ats_optimizer.py`

Technical Details:
  - Ingestion Engine: `pdfplumber` extracts text while preserving spatial layout; 
    `python-docx` parses Word documents.
  - 5-Pillar Scoring Formula:
      1. Skills Density & Contextual Relevance (35 pts)
      2. Action Verbs & Quantified Metrics (25 pts)
      3. Contact Completeness & Profile Links (15 pts)
      4. Section Formatting & Single-Column Structure (15 pts)
      5. Keyword Distribution & Seniority Tone (10 pts)
  - Data Architecture: Separates immutable original upload (`raw_extracted_content`) 
    from live editable working copy (`working_content`) and custom `section_order`.

API Endpoints:
  - `POST /api/profile/upload` — Upload resume file, extract entities, compute ATS score.
  - `GET  /api/profile` — Fetch active profile with complete ATS breakdown.
  - `POST /api/profile` — Save manual updates to working profile content.
  - `POST /api/profile/reorder` — Update custom section display sequence.

PHASE 2: INDIA MULTI-SOURCE STARTUP DISCOVERY ENGINE
--------------------------------------------------------------------------------
Status: [COMPLETED]
Primary Objectives:
  - Aggregate tech roles and internships from Indian startup platforms.
  - Categorize roles into standard tech domains (FinTech, SaaS, AI/ML, EdTech, D2C, etc.).
  - Normalize locations across Tier-1/Tier-2 Indian tech hubs (Bengaluru, Mumbai, 
    Gurugram, Pune, Hyderabad, Noida) and remote openings.
  - Eliminate duplicate cross-posted listings.

Files & Components Involved:
  - Backend: `backend/app/agents/agent2_discovery.py`, `backend/app/db/models.py` (`JobModel`), 
    `backend/app/schemas/schemas.py` (`JobSchema`)
  - Frontend: `frontend/src/components/JobDiscovery.jsx`

Technical Details:
  - Source Aggregators: Internshala, CutShort, Instahyre, Wellfound (AngelList), 
    Naukri, Foundit, and YourStory.
  - Deduplication: Deterministic hashing using normalized company name, role title, 
    and city to prevent duplicate job records.
  - Internship Support: Flags `role_type="internship"` with stipend metadata and 
    early-career eligibility tagging.

API Endpoints:
  - `GET  /api/jobs` — Filter and search discovered jobs by domain, source, city, role type.
  - `POST /api/jobs/discover` — Trigger live discovery sweep across startup boards.

PHASE 3: MULTI-CRITERIA SEMANTIC MATCHING ENGINE (0-100%)
--------------------------------------------------------------------------------
Status: [COMPLETED]
Primary Objectives:
  - Implement a weighted multi-dimensional compatibility engine comparing candidate 
    profiles against discovered job specifications.
  - Provide transparency into matching skills and missing skill gaps.
  - Establish a qualification gate (Match Score >= 65%) to filter qualified opportunities.

Files & Components Involved:
  - Backend: `backend/app/agents/agent3_matching.py`, `backend/app/db/models.py` (`MatchModel`), 
    `backend/app/schemas/schemas.py` (`MatchSchema`)
  - Frontend: `frontend/src/components/JobDiscovery.jsx`, `frontend/src/components/TailoringHub.jsx`

Technical Details:
  - Weighted Match Formula:
      Match Score = (0.40 * Skill Overlap) + 
                    (0.25 * Domain Relevance) + 
                    (0.15 * Location Score) + 
                    (0.20 * Semantic Match)
  - Internship Weighting: For internship roles, experience duration penalty is 
    waived, shifting weight to project stack and programming fundamentals.

API Endpoints:
  - `GET  /api/matches` — Retrieve candidate matches with 4-component score breakdowns.

PHASE 5: SMART ATS APPLICATION ROUTER & STAGED AUTO-FILL ARCHITECTURE
--------------------------------------------------------------------------------
Status: [COMPLETED]
Primary Objectives:
  - Classify discovered application links into auto-apply eligible ATS vs manual review.
  - Implement Playwright-based automated form-filling for Greenhouse, Lever, and Ashby.
  - Enforce `dry_run=True` safety rails and discovery-only policies for protected boards.

Files & Components Involved:
  - Backend: `nextopportunityfind/routing/source_router.py`, `nextopportunityfind/apply/greenhouse_apply.py`, 
    `backend/app/main.py`, `backend/app/db/models.py` (`ApplicationModel`, `ApplicationEventModel`)
  - Frontend: `frontend/src/components/ApplicationPipeline.jsx`

Technical Details:
  - Routing Logic: Recognizes verified ATS domains (`boards.greenhouse.io`, `jobs.lever.co`, 
    `jobs.ashbyhq.com`) as auto-apply eligible.
  - Safety Enforcements:
      * Discovery-Only: LinkedIn, Naukri, and Internshala are enforced as discovery-only 
        and routed strictly to the Manual Review Queue.
      * Dry Run Default: Playwright script fills out the form in non-submitting inspection 
        mode, awaiting candidate confirmation before submission.

API Endpoints:
  - `GET  /api/applications` — Fetch applications in the pipeline.
  - `PUT  /api/applications/{id}` — Update application status, candidate notes, and form autofill data.
  - `POST /api/applications/{id}/submit` — Execute / simulate ATS submission with audit logging.
